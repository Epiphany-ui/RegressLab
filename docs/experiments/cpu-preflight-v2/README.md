# 第二轮CPU开发预实验：固定HGC没有显示收益

结论：修复了首轮的模型节点复用问题，真实训练、HGC和工件审计均完成；但**当前固定HGC在该CPU开发设置中检出弱于margin，增加的成本也没有换来收益**。事件量筛查、描述性接近规则和成本筛查均未通过。它是有用的负面开发证据，不是对所有历史群体方法的普遍否定，也不是正式盲评结论。

本轮沿用字符TF-IDF＋多类逻辑回归，没有使用大语言模型。HGC是选择测试样本的算法，不是另一个任务分类模型。正式TEST没有进入训练、模型预测或评价。

## HGC机制观察

HGC确实在全D历史上构建了风险组，六链各14—25个保留组，均未触发无组退化。固定目标在B=100时群体覆盖G接近1，但没有转化为未来负翻转检出优势。每链HGC与Facility的检出数相同；两个套件的100个成员仅重合68—75个，选择顺序也不同，所以不能解释为HGC代码直接退化成Facility。

这表明“历史风险覆盖代理目标优化成功”不足以证明“未来检出有效”。表面群体、当前正确过滤、更新间风险迁移和稀疏事件都可能影响观察；本轮未做完整四机制模拟或消融，不能仅据此断言是哪一个因素导致失败。

## 成本与资源

24次训练均收敛并保存/重载一致，单fit约2.33—4.77秒；完整流程测得115.14秒、峰值RSS 636.7MiB，CPU限2线程。原报告及本地依赖锁记录环境；未执行GPU训练。总墙钟不含此前下载/依赖安装，也不包含本次结束后的审计。

基线按方法/seed测量至最大预算，并额外以B=100重算计时、核对相同套件。成本表包含公共验证、HGC风险/相似度/贪心；P表示构建只向Facility/KCenter/HGC收费。主预算目标执行统一测`text -> transform -> predict`，同P全量及每个套件各5次、固定顺序取中位数。

在历史和f2概率已缓存的有利情景中：全P推理约6.36—6.67毫秒；HGC选样约57—82毫秒，另加约14—15毫秒表示及所选样本推理，总比值为11.01—14.61，未满足≤0.8的成本规则。这个小CPU设置不支持当前HGC的节约主张。

margin在同一缓存情景的成本比约0.58—0.64；若再计入实测重建全P的f2概率，约为1.61—1.83。因此不能把“margin检出强”直接等同“任意场景部署都省钱”。历史创建、模型训练、跨更新复用/摊销也未被证明免费。固定顺序、warm缓存和单次选择计时有噪声，结论限于当前测量口径。

计时额外执行2,610次目标predict，包含278,055行重复样本执行；它们属于研究测量成本，不是独立样本数或B=100部署调用数。首次主评分还执行了完整DEV的目标概率与标签一致性检查；不能把研究中实际全量执行的费用删去后声称已经节约。

## 判定与下一步

本轮完成了可运行性、先训练后全局身份门禁、固定HGC和成本审计；**三项事前开发筛查均不通过，正式G0—G3也未因此获准**。

不启动第3轮lambda/m、特征或seed寻优，不直接扩到GPU大矩阵或建设研究UI。下一步应把这两轮负面结果整理成研究决策材料，先核对历史群体风险是否具有可迁移信号：开展事前固定的最小机制模拟/诊断，并补独立外部数据的模型无关来源与类别支持审计。它们不能改写本轮结果，也不应成为同一DEV上的继续寻优。

只有出现独立机制支持或明确的新科学问题，才另行设计研究；否则应考虑简化为强基线比较/适用条件研究，收缩当前HGC主张。HGC普遍有效、独立外部验证、Risk-LR/Behavior-Anchor/Grad-PD、四机制实验和神经迁移均未完成。
