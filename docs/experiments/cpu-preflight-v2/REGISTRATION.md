## 目的与边界

修复首轮跨链等价节点问题，取得每方法、主预算B=100的可比成本，并用最小HGC回答：在该CPU开发设置中，历史群体信息是否提供margin之外的额外价值。本轮仍使用已经看过的DEV_SELECTOR，只能作为开发筛查，不能改名为正式盲评。TEST仍仅用于无模型数据组件审计，不进入任何模型输入、选样或预测评价。

仍用MASSIVE 1.1 zh-CN组件清理后的TRAIN=10,966、DEV_MODEL=931、DEV_SELECTOR=935，同一来源hash和DEV划分。DEV两侧各缺2类，保持原分区并报告支持，不为补类别/增加翻转看目标后搬动样本。外部CLINC、神经训练、Grad-PD等不在本次执行范围，缺项明确保留。

## HGC固定实现

按[源算法](../../research/v2/source/03-algorithm-spec.md)公式实现，并补充预登记的特征、排序和过滤边界；lambda=0.5、m=30、k=3、每转移组机会数门槛10、最多30组、D成员Jaccard≥0.9去重。按w降序、P支持降序、canonical谓词UTF-8同分。风险从全DEV_SELECTOR的f0—f2估计，不仅从P估计；选样和表示只用P。

五特征为gold标签、归一化字符长度箱、否定、数字、问号；只枚举单条件和不同特征两条件合取，布尔false也参与。长度分界10/20/40，按NFKC与空白折叠后的Python len计数（含内部空格）。否定词固定为不/没/无/别/未/不要/不能/not/no/never/without，中文子串、英文忽略大小写词边界；数字用Unicode str.isdigit，问号为`?`或`？`。不使用目标错误特征或自由元数据。

全局旧正确机会数为零的转移排除；组支持不足的u记零但仍占有效转移分母。按收缩超额风险与重复比例计算w；先排除P为空或w≤0的组，再按固定排序做D成员去重和30组截断；不让不可入选的组占cap，记录去重损失和低支持。固定同Facility的分层hash锚点（至多256）、非负P内字符TF-IDF余弦，精确贪心。无风险组明确fallback=Facility；所有预算共享同一序列前缀。此次不开发lambda/m网格，也不根据已看结果追加特征。

## 事前筛查规则

- 可评价事件筛查：每家族至少2条链各有≥20条未来翻转。20只使单事件Recall变化不超过5个百分点，不是功效计算或正式G1认可；失败时完整报告所有稀疏/零事件链。
- 描述性HGC比较：逐链先算Recall@100，再按家族等权平均；每家族HGC减margin均值须≥−0.03才记“描述性接近规则满足”。不是统计非劣检验，不把选样seed当独立训练链。
- 成本筛查：在历史/f2概率已缓存的有利情景中，将HGC选样、P表示构建和所选100条目标推理相加，与同一P全量推理比较，要求每链比值≤0.8。仍不等于已证明真实部署节约；历史缓存创建/更新、参考分数和共享建库另报。
- 不以上述局部规则替代正式G0—G3或全核心方法验收。失败/不确定时报告条件或负结果，不开启第3轮寻优；转向简化/比较研究或制定新的科学问题。

## 成本与保存

冻结前，每方法/seed计算至最大预算并记录耗时；另以B=100单独运行同一选择器作成本probe，结果必须与已选主预算套件相同。HGC单记风险搜索、相似度和贪心时间；每次基线部署计入公共验证费时，HGC自身验证已包含在total内，不重复收费。表示、历史预测及全P参考分数重建分别测量，不把20个seed累计费时当一次部署成本。

全矩阵冻结后才显式预测f3开发目标。对同一P全量及每方法/seed的B=100套件，各做5次固定顺序的`text -> transform -> predict`测量，记录全部样本和中位数；属于warm-cache近似，顺序未随机化，微秒级结果不夸大。所有重复f3执行是研究测量支出，不能从物理成本中隐去。套件较少样本不能通过简单按比例推算耗时。

完整gold/ID/历史概率/组/套件/权重/语义身份和计时留在Git忽略的本地新目录，便于复核完整P与未来分母。本轮将提交代码、配置、登记、去原文的报告和审计摘要，不提交原文/逐样本预测/模型。180秒训练检查仍是fit返回后的软门禁；无GPU训练或显存性能主张。
