# 项目章程与可行性基线

版本1.3 · 2026年10月22日。范围权威见[PRODUCT](PRODUCT.md)，版本来源见[19](19-model-version-protocol.md)。设计已获用户授权同步，软件和模型效果尚未实现、测量。

## 1 价值与交付

模型继续训练后可能改善平均分，同时使一部分旧正确输入变错；negative flip是已有概念[S01]。本项目交付面向固定标签大模型分类应用的本地测试工作台，串联数据/模型身份、真实预测、D分组、C独立确认、审查、冻结套件和后续版本重放。

论文题目为《面向大模型分类应用的退化诊断与回归测试系统的设计与实现》，按应用开发类规划，具体登记由学院确认。工程机制、工作流、测试和真实应用验证是主体；算法组合和跨版本收益待实测，不承诺新颖性或发表。

## 2 范围

MASSIVE1.1中文单标签意图；FastAPI＋Vue3/TypeScript；PostgreSQL与单Worker；受限CPU分类器、Ollama已安装模型、严格外部预测导入。主实验是小模型TRAIN-only LoRA检查点更新，逻辑回归（LR）重新训练作对照，API可选。训练脚本作为实验准备交付，不开发Web大模型训练平台。C/A不能供调参、训练、选择检查点或界面案例浏览。

保留成对指标、最深2原子分组、一次确认、不可变套件、恢复、报告、认证及审计。开放生成、多用户SaaS、自动训练修复、生产发布/回滚不纳入。解释接口仅为关闭的兼容设计。

## 3 资源与风险

用户设备为桌面端3060、6GB显存。主候选0.6B，先32步训练烟测、DEV分类与稳定性检查；不保证可训、耗时、精度和自然退化数量。1.7B需测量后决定，不将推理可运行等同训练可完成。完整60标签提示词长度、CUDA/PEFT依赖、权重与adapter导出均为早期风险。

Web/统计运行与CUDA训练环境分离；离线须先准备权重、数据和依赖。磁盘记录权重、检查点、原始响应和备份实际大小，不沿用原CPU方案10GB假设。GPU训练和推理不得同时抢资源；成本包含准备、训练、全量预测、选择及后续回放。

| 风险 | 处置与诚实出口 |
|---|---|
| 6GB训练失败/过慢 | 先试0.6B，开发阶段缩预算或单独冻结资源方案；未通过不承诺主实验 |
| 标签列表或序列被截断 | 完整扫描token，超限停止profile，不能静默丢类别/文本 |
| 推理不稳定 | DEV100例×3；未通过只描述，不宣称独立确认的权重退化 |
| 错把检查点当重复实验 | 同run只算一条相关链，种子和行不能增加独立训练数量 |
| 没有自然退化/分组功效低 | 无候选、证据不足或NA如实保留，人工注入只作软件测试 |
| 选择算法看过未来错误 | 冻结套件hash和时间后才能生成/解封后续预测；违规标探索 |
| API别名或身份漂移 | 默认不依赖；记录调用时间和已知身份，不能冒称可调权重 |
| 开发范围膨胀 | 默认固定选择算法，五基线两消融；自适应调整走17额外条件 |
